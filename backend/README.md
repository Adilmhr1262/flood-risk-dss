# Flood Risk DSS — Backend

FastAPI backend for the **Flood Risk Prediction and Early Warning Decision Support System**.
Provides role-based APIs (authority / NGO / public), a rule-based v1 risk engine,
a scikit-learn machine learning training pipeline, and GIS-ready endpoints.

## Setup

```bash
cd backend
python -m venv .venv && source .venv/bin/activate
pip install -r requirements.txt
cp .env.example .env        # then edit DATABASE_URL and SECRET_KEY
```

## Run the API

```bash
uvicorn app.main:app --reload --port 8000
```

- Health check: `GET /health`
- Interactive docs: `http://localhost:8000/docs`
- API base: `http://localhost:8000/api/v1`

> Endpoints that persist data (register, login, predictions history, dashboard
> aggregates, GIS layers, alerts, reports) require a reachable PostgreSQL
> database (`DATABASE_URL`). The `/risk/predict` endpoint runs the risk engine
> without a database; it only skips persistence when the database is down.

## Schema contract

`database/schema.sql` (PostgreSQL 15 + PostGIS) is the authoritative schema and
the ORM layer (`app/models/`) mirrors it exactly:

- Every table uses a UUID primary key named `id` (generated by
  `gen_random_uuid()`); all path parameters (`/users/{id}`, `/alerts/{id}` …)
  are UUIDs.
- Locations live in `geographic_data` (`district_name`, `province`,
  `geom` as `GEOMETRY(Point, 4326)`, `elevation_m`, `river_distance_km`,
  `slope_deg`, `population_density_per_km2`, `vulnerability_index`).
  Flood events, predictions, alerts, and shelters link to locations via
  `geographic_id` — never via a plain district string column.
- Predictions store the feature vector in `input_features` (JSONB) and
  `main_factors` / `recommendations` as native `TEXT[]` arrays; `created_by`
  records the requesting user.
- The `user_role` enum (`'authority'`, `'ngo'`, `'public'`) is defined in SQL;
  the ORM maps `role` as text constrained to those three values.

## Roles & permission matrix

Authenticate via `POST /api/v1/auth/register` or `/login`, then send the
returned access token as `Authorization: Bearer <token>`. Both endpoints
return an access + refresh token pair; `POST /auth/refresh` rotates the pair
and `POST /auth/logout` is the documented stateless logout (client discards
both tokens).

| Capability | `authority` | `ngo` | `public` | `volunteer` |
|---|---|---|---|---|
| Dashboard (summary, trends, frequency, distribution) | ✅ | ✅ | ❌ | ❌ |
| Risk assessment (`/risk/predict`, history, model info) | ✅ | ✅ | ✅ | ✅ |
| GIS layers (risk, historical, shelters, districts, contacts) | ✅ | ✅ | ✅ | ✅ |
| Mobile endpoints (`/mobile/*`: risk, alerts, nearby shelters, contacts) | ✅ | ✅ | ✅ | ✅ |
| Flood sighting reports (`POST /mobile/report-event`) | ✅ | ✅ | ✅ | ✅ |
| Alerts: read | ✅ | ✅ | ✅ | ✅ |
| Alerts: create / deactivate | ✅ | ✅ | ❌ | ❌ |
| Alerts: delete | ✅ | ❌ | ❌ | ❌ |
| Reports (CSV exports) | ✅ | ✅ | ❌ | ❌ |
| User management (`/users`) | ✅ | ❌ | ❌ | ❌ |

`authority` = Disaster Management Authority (full access),
`ngo` = NGO / Relief Organization (reports, affected areas, shelters),
`public` = Public User (risk checking, alerts, emergency information),
`volunteer` = Community Volunteer (public read access + flood sighting reports).

## Risk engine (v1)

`app/services/risk_engine.py` — deterministic, data-driven baseline scorer.
Nine features are normalised to 0–1 and combined with fixed weights (sum = 1.0):

| Feature            | Weight | Normalisation                              |
|--------------------|--------|--------------------------------------------|
| rainfall_mm        | 0.25   | x / 200 mm                                 |
| river_distance_km  | 0.18   | inverse: 1 − x / 10 km                     |
| elevation_m        | 0.15   | inverse: 1 − x / 500 m                     |
| prev_flood_events  | 0.12   | x / 5 events                               |
| humidity_pct       | 0.08   | (x − 40) / 60                              |
| slope_deg          | 0.08   | inverse: 1 − x / 15°                       |
| population_density | 0.07   | log-scaled, saturates at ~10,000 / sq km   |
| temperature_c      | 0.04   | (x − 20) / 20                              |
| last_severity      | 0.03   | x / 3 (0=None, 1=Low, 2=Medium, 3=High)    |

Levels: **LOW** < 0.33, **MEDIUM** < 0.66, **HIGH** ≥ 0.66. Significant factors
and per-level recommendations are returned with each assessment.

## Machine learning training

```bash
# Train on the sample data and print metrics
python -m ml.train --data ml/sample_training_data.csv --out models/random_forest.joblib

# Use the MLP (multi-layer perceptron) variant
python -m ml.train --data ml/sample_training_data.csv --out models/mlp.joblib --model mlp
```

The pipeline (`ml/pipeline.py`) trains a `RandomForestClassifier` by default
with optional `MLPClassifier` and `XGBoost` variants. Metrics reported:
accuracy, precision, recall, F1, ROC-AUC. `ml/sample_training_data.csv`
contains ~120 synthetic but plausible rows for development.
